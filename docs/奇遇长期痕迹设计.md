## 二、现状勘察（2026-09-22 核实）

### 2.1 奇遇系统（P10，happenstance_data.dart / mixin_happenstance.dart）
- **数据模型**：`HappenstanceDef`（id/title/scene/seasonTags/locationKeys/minGrade/weight/baseChance/outcomes 2~4 个）。
- **结局模型**：`HappenstanceOutcomeDef`（title 按钮文案 / text 叙事 / effect 结算）。
- **效果模型**：`HappenstanceEffectDef`（reputationDim/reputationValue/housePoints/galleons/energy/npcId/npcAffection/itemName）。
- **记档现状**：`Player` **无奇遇完成记录字段**（grep 无 hit）——奇遇结束后只剩数值变化，事件本身不留痕。

### 2.2 声望系统（player.dart:96-114）
- `Reputation playerReputation`：六维 academic / social / combat / moral / leadership / dark。
- 派生：总声望 = 五维均值；堕落度 = (dark - moral).clamp(-100, 100)。

### 2.3 角色档案（mixin_commands.dart:758-760）
- `/档案 回忆`：回看人生大事记（现有入口，可承载奇遇痕迹展示）。

## 三、方案设计

### 3.1 核心思路：让每场奇遇都"留下来"
> **奇遇完成后，把「事件 + 玩家选择 + 结局」沉淀为一条角色档案条目，进入 `/档案 回忆` 大事记，并在学期末快讯回顾/终章中被引用。**

### 3.2 记档字段（Player 新增 1 个）
- `happenstanceLog: List<HappenstanceLogEntry>`：已完成奇遇的流水记录。
- `HappenstanceLogEntry`（新模型，不入存档顶层，作为 Player 内嵌列表）：
  - `id`：奇遇 id
  - `title`：奇遇标题
  - `outcomeTitle`：玩家选择的结局按钮文案
  - `outcomeText`：结局叙事（可截断，如前 100 字）
  - `week`：完成周数（`gameWeek`）
  - `term`：完成学期（first/second/summer）
- 存档 21 → 30（决斗社 5 + 魔药部 3 + 魁地奇 2 + 快讯 2 + 奇遇 1 = 13 字段；同批实施则 21 → 34）
- 容量：上限 50 条（超出删最旧，同来信 50 上限口径）。

### 3.3 写入时机
- 奇遇结局结算处（`mixin_happenstance.dart` 选择结算段）追加：完成奇遇后 `player.happenstanceLog.add(...)`。
- 行为不变：只加记录，不动结算数值。

### 3.4 展示与引用（三处落点）
1. **`/档案 回忆` 大事记**：追加「奇遇」小节，按时间倒序列出已沉淀奇遇（title + outcomeTitle + 周数）。
2. **学期末快讯回顾**（联动 16c 快讯社头版事件）：年度快讯回顾自动引用本学期奇遇日志条目，作为"大事"素材。
3. **终章引用**：终章角色总结可统计奇遇数量/类型分布（如「你曾在城堡里经历了 N 场不期而遇」），汇入终章叙事。

### 3.5 映进声望（轻量）
- 规划文档要求「映进 P14 声望」——不直接给数值（避免重复结算），而是在**总声望展示**侧提供「奇遇经历」上下文：
  - 已沉淀奇遇 ≥ 5 条：档案声望段追加「你有 N 段不期而遇的经历，它们塑造了你的行事风格」。
  - 已沉淀奇遇 ≥ 15 条：追加「城堡的每个角落都认得你」。
- 纯展示性注入，不改声望数值，零平衡风险。

## 四、数据层改动（Player 新增 1 字段 + 1 内嵌模型）

## 六、风险与边界
- **行为不变红线**：不动奇遇结算数值与抽取逻辑；只加一条只读日志。
- **容量克制**：上限 50 条 + 截断 outcomeText，防存档膨胀。
- **与 UI 无关**：纯玩法层，不触碰本轮 UI 收敛工作区。
