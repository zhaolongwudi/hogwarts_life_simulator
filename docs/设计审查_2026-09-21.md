## 一、总体判断

国内独立游戏里少见的、**数值意识成熟**的项目。值得单独表扬的设计：

1. `compressAffectionDelta` 注释体现了对「AI 生成 vs 数值校准」核心矛盾的清醒认识（大事件+20 与日常+8
   落地不再都是 +5）。
2. `affectionLandingFor` 让 prompt 侧自动跟随压缩函数的落地区间——治了"提示词教一套、程序做一套"的割裂。
3. 「平行世界·采纳」实现为"存成想过的事"而非真的发生——避免玩家一句话改一次世界的世界观崩坏。
4. `effectiveAttr` 用 `_scarPenaltyKey` 缓存疤痕惩罚、`houseDisplayName(houseKeyOrNull)` 判空——
   都在小细节上避真实的坑。
5. `foreshadow_data.dart` 用中文二字组重合度匹配伏笔闭环，除以较小集合而非并集（避免长文本稀释）、
   双门槛（比例 0.30 + 绝对数量 4）防误关——思路非常成熟。
6. 长期记忆分层：持久层 9 分豁免淘汰、身份层 10 分豁免容量护栏、注入配额与存储配额同源
   （`kT0InjectionPersistentQuota = kMaxPersistentKeyFacts`）——从类型层面消除"存着读不到"。
7. director_beat 的转折概率 = 基础 0.15 + 0.10×间隔（封顶 0.55）+ 低张力场景减半 + 钩子未完强制推进。

## 二、🔴 一级问题（数值可信度）

### 1. GoalRequirement 与 CareerDef 系统性冲突
| 目标 | GoalRequirement 要求 | CareerDef 入职要求 |
|---|---|---|
| auror 傲罗 | combat 60 + dda ≥ 75 | combat 60 + dda ≥ 70 |
| healer | moral 60 + **herbology** ≥ 70 | moral 55 + **potions** ≥ 70 |
| minister | leadership 70 + social ≥ 75 | ministry: leadership 50 + social ≥ 60 |
| potion_master | academic 60 + potions ≥ 80 | （无对应职业线） |

- 属性门槛错开 → 毕业结算判"目标未达成"，/职业 却能入职，两条路自相矛盾。
- 属性维度错位（healer 目标看 herbology，职业看 potions）。
- 声望门槛差 20（minister 70 vs 50）。
- **修法**：两份表从同一数据源派生，或在 buildPrompt 对玩家显式并列展示。

### 2. 目标门槛脱离期望分布（数学不可达）
- growthExpectation.max：dda 80 / potions 75 / theory 70 / flying 65
- goal.requirement：potions 80 / theory 80 / flying 80 / dda 75 / spell_understanding 75
- `attrGrowthPerYear = 8`，7 年理论增量 56；要命中上限需每年稳定拿到 attrGainMax，
  任何一次波动就掉出区间 → **goal_achieved 成就基本无人解锁**。
- 目标系统达成率应控制在 30~60%。
- **修法（二选一）**：① 下调门槛至 max-5；② 加专精加成：某学科持续高分时年增长 8→12。

### 3. 学院杯激励结构失衡
- houseCupActivityPoints：quidditch_win 30 / exam_top 15 / forest 8 / duel 5 / quest 5 / classroom 3
- 其他三院按上学日逐日增长（kHouseRivalDailyMin~Max × ~120 上学日 ≈ 240~360 分/年）
- 高频低奖（classroom 3）vs 低频高奖（quidditch 30）错配 → 玩家学院分常年追不上 rival 自然增长。
- **修法**：classroom 应是累积型主力（提权），quidditch 保持爆发型但单次不宜过高。

## 三、🟠 二级问题（体验质量）

### 4. compressAffectionDelta 分段非连续
- raw=5、6 都映射 5；raw=20→9、21→10；三段斜率 1/0.4/0.2/0 接缝跳变。
- **修法**：改单调平滑 `mapped = min(10, round(sqrt(d*2)))` 一类幂律。

### 5. 快进破坏学业反馈闭环
- fastForwardDays 允许 365 天跳跃，跳过学时消耗直接触发 _onSchoolYearStart 考试结算。
- mixin_systems 自曝"7 年约 6 万回合"——该数字本身就是 UX 警示灯。
- **修法**：快进期间按天数比例补偿少量属性（模拟假期自学），否则快进性价比反而低于逐回合。

### 6. 表白系统门槛叠加过度
- 五前置同时满足才进入掷骰：affection≥85 + romanticEvents≥2 + crushMatureDays≥14 + base 0.2/max 0.6。
- 30 天无互动起衰减 1~2/周 → 攒 85 过程中断联即掉。稀缺性叠太狠。
- **修法**：至少拆一项为软门槛（概率乘数），避免"努力几十小时仍被前置卡死"。

### 7. P14 与 kDailyActivityLimits 频次口径不一致
- 社团任务"每回合最多 +1"，kDailyActivityLimits 按游戏日计 → 认知混乱 + 测试口径难写。
- **修法**：统一到同一种口径（建议按行动次数）。

### 8. selectYearGoal 抽取无多样性保障
- `(schoolYear-1+seed) % pool.length`，seed=turnCount → 相同起点所有玩家得到完全相同的学年目标序列。
- **修法**：加权随机 + 排除近期已用 + 关联 currentGoal。

### 11. 功能残缺点
- **论坛评论只 +1 数字，不写评论文本**——玩家点评论按钮只是数字增长，评论栏无字。

### 12. 传闻生成缺去重
- `_maybeGenerateRumor`：跨天 20% 概率、从 recentEvents 随机取一条改写，无近 N 天去重、
  无"是否已被传闻化"标记、无总量护栏。

### 13. CI 测试夹具策略双刃剑
- 默认关掉全部新系统保证 1900+ 既有用例稳定，代价是**默认配置与测试配置完全不同**，
  线上问题无法用现有测试复现。建议 CI 加一份"全开 smoke"套件。

### 14. 文档漂移
- PROJECT_GUIDE v5.0.2 / 规划文档基线 v4.8.4 / README 滞后。建议文档纳入 CI 同步流程。

### 15. foreshadow 门槛偏严（第二轮补充）
- `kLoopMatchThreshold 0.30 + minShared 4`：作者注释自己承认"小天狼星留钥匙 →
  钥匙打开尖叫棚屋"只有 2 个共同二字组会被**漏关**——道具类伏笔永远收不了。
- **修法**：命中"人名 token + 物件名 token"时走实体一致性放行通道，别硬套比例。

### 16. scene_illustration 是全局颜色收敛的最大漏网（第二轮补充）
- 30+ 条 `Color(0xFF...)` 硬编码，违背 PROJECT_GUIDE §3.5"新代码不写裸色值"。
- **修法**：纳入 MiuiColors 场景 token 家族，或文件头显式豁免并说明理由。

### 17. prompt 规则密度过高无分级（第二轮补充）
- narrative_prompts 一次塞约 2500 字铁律（质感/时间/场景/写作/多样性/文风/在场）。
- **修法**：分 T0 常挂（时序/在场/场景合法性）、T1 风格抽样注入、T2 罕见踩坑按状态动态挂载。

### 18. 长期记忆缺"情感权重"（第二轮补充）
- 双通道（importance + freshness）无主观维度：救命之恩 vs 课堂优秀可能同分 8。
- **修法**：落库时按事件类型映射微调（生死/表白/背叛至少 +1），仅生产端调参不动结构。

### 19. 五部原著剧本缺乏静态一致性校验（第二轮补充）
- story_data 五文件共 532KB，跨书时间/年龄一致性无人校验。
- **修法**：CI 加脚本抽出带 timestamp 的节点，校验书内时间单调 + 年份区间。

## 六、玩法增量提案（单机自玩向）

> 设定前提：只服务玩家一人，无需留存/新手引导 → 做"每一局都独一无二的一生"，
> 不做"关卡丰富度"。以下按投入产出排序。

### 第一梯队（1~2 天）

**【P1】心结系统（代价显性化）**
- 现有 scars 只走属性扣减且触发面窄。扩成"每次得意都有代价"暗线：
  - 黑魔法成功 → +dark_reputation 的同时累积 weightOfSoul（灵魂重量，毕业终章体现）
  - 连续 3 次欺骗同一 NPC → 该 NPC 拒收礼物，当面说谎 30% 概率被告发
  - 拒绝教授求助 3 次 → 相关学科期末降一档
  - 抢队友功劳 → 该队不再邀请
- 成本极低：Player 加 `Map<String,int> weights`，落库时写入，提示词注入一行。

**【P2】命运预言**
- `_onSchoolYearStart` 钩子：九月调用 SUMMARY 短 prompt，结合近一年 keyFacts/openLoops/affections
  生成一句 30 字以内的含糊预言，存 `player.prophecies`。
- 毕业结算时全部摆出，逐条评"应验/未应验/部分应验"。
- 把 7 年串成"宿命感"框架，全部基于现有数据派生，~200 行。

**【P3】梦境频道**
- `/睡觉` 独立入口而非快进：25~50% 概率触发一场梦（深夜 2~4 点概率更高）。
- 梦 = keyFacts 1~2 条 + openLoops 1 条 + 随机隐喻元素 → AI 拼 100~200 字非线性叙事。
- 梦最适合 AI 生成（无现实逻辑约束），且让"睡觉"本身有诗意。

### 第二梯队（3~5 天）

### 🟠 20. 「压缩 → 衰减」两步连乘把日常好感杀成零

`mixin_response_affection.dart` 第 170~177 行的调用顺序：

```dart
delta = Balance.compressAffectionDelta(delta);   // raw=8 → 6
delta = _applySocialCost(npc.id, delta);          // × 0.8 → 5；× 0.3 → 2
_checkMajorEventImmunity(npc, rawDelta, reasonText);  // ← 只在免疫判断之后已经晚了
```

- **问题**：日常 raw=+5 连续 4~6 次互动被衰减压到 ×0.6~×0.3 = 1~2 点/回合并封底 1——刷一整周感觉完全被吞掉。
- **更严重**：`_checkMajorEventImmunity` 在 `_applySocialCost` **之后**才被调用（第 173 vs 177 行），
  所以"重大事件免衰减"这条机制设计意图明确写下的功能，实现上完全不生效——它只记录了
  `npc.majorEventDate` 但没有真正阻止衰减。救命之恩 raw=+12 → 压缩 8 → 依然走衰减系数。
- **修法二选一**：① `_checkMajorEventImmunity` 提前调用并把结果作为衰减函数的旁路开关；
  ② `_applySocialCost` 内部根据 `npc.majorEventDate` 距今 N 天自动绕过衰减。

### 🔴 21. P14 社团晋级曲线太陡（数学算给你看）

`club_data.dart` 阶位门槛：**0 / 60 / 140 / 250 / 400（传奇）**
单次干系事结算：+10~+15 积分/回合，带冷却 kClubCooldownTurns

理论最优：平均 +12.5 × 每 3 回合一次 ≈ 每年 ~2000 分——可达顶级。
但现实需同时满足三个前置：
1. 本回合未挂待处理的奇遇/羁绊/回信（这三样一开就让社团静默退出）
2. 距上次干系事过了冷却
3. **行动文本必须精确子串命中 activityKeywords**（`action.contains(kw)`，不做别名归一）

第三条是关键陷阱："和魁地奇队的朋友切磋了一下飞天扫帚"未必命中 broom 社关键词。
"练球""训练""和罗恩一起"这些近义词全部漏网 → 玩家大多数日常互动都对不上任何社团。
攒到传奇 400 分要花半年以上反复精挑措辞——"归属回报"落地成了"文字游戏"。

**修法**：
- 关键词表引入别名映射（每个社团至少 15 个同义入口）；或
- 改加权模糊匹配（复用项目已有 bigram 重合度思路）；
- 传奇 400 → 260，或在 200 分处插一档"资深成员"中间奖励缓解挫败感。
