# 决斗社季度赛 · 设计预研（2026-09-22）

> 状态：已实现（批次 B/C，2026-09-22 起生效）｜ 来源：规划文档第一梯队「社团专属小玩法」第一项
> 「决斗社季度赛（复用 `/决斗`）」——每社给一个可玩入口，别只做标记记分。

## 一、需求来源

`docs/工作思路与后续规划.md` 第一梯队：
> **社团专属小玩法**：决斗社季度赛（复用 `/决斗`）、魔药部限时配方（复用 `/使用` 药水）、
> 魁地奇队训练（复用 P8 变体）、快讯社头版事件（复用 P10 奇遇池）。每社给一个可玩入口，
> 别只做标记记分。

当前社团已有：日常记分晋升（P14）、跨回合任务（P15）、晋升回访信（P16）、社团×学院杯联动（P18）。
缺一个"可玩入口"——季度赛就是让玩家**主动去打**，而不只是离线行动被动攒分。

## 二、现有基础勘察（已核实）

### 2.1 决斗引擎（`lib/mixins/mixin_play.dart:1037` `duelNpc`）
- 入口：`/决斗 <人名>` 或 `/决斗` 随机挑战；每日次数上限 `canDoDaily('duel')`
  （`kDailyActivityLimits['duel']`）。
- 对手过滤：仅在校生（grade >= 1，排除教职/成人），同一天重复挑战同一人有冷却。
- 时间：一场 60 分钟（`advanceTimeForAction('决斗')`）。
- 战力：`_playerPower()` = (dda + spell_understanding + magic_control)/3 + 装备战斗加成
  + 宠物助战（羁绊≥40 +3）+ 杖芯加成（龙心腱/凤凰羽）。
- 胜负结算：赢 +学院杯分（`10 * decay`，clamp 1~10）、首胜成就 `first_duel_win`、
  首次打赢某 NPC +2 好感；输可能致伤（`_pendingDeathCause`）。
- 已击败集合 `_duelBeatenNpcIds`：打赢只加一次好感，防刷——**但赛季分不该受此限制**
  （赛季要的就是反复打）。

### 2.2 社团引擎（`lib/mixins/mixin_club.dart`）
- 三层：①`maybeRunClubActivity` 匹配行动→记分（10~15 确定性随机，日预算
  `kDailyActivityLimits['club_activity']`）②跨阶发奖（`_rankBonusLines`：属性/学院分/声望）
  ③面板与加入退出。
- P15 任务：`ClubTaskDef`（接取→按干系事推进→领奖，日预算 `club_task`）。
- P18 联动：日常记分 +1 学院分、任务完成 +3 学院分（`addHouseCupPoints`）。

### 2.3 时间体系（`lib/models/world_state.dart` + `lib/mixins/mixin_systems.dart:682`）
- 学期：9-12 月第一学期（term='first'）、1-6 月第二学期（term='second'）、7-8 月暑假。
- `worldState.term` 字段已存在；`gameWeek` 按 7 天桶推进；学年 `academicYear`（如 1991-1992）。
- 学年结算 `settleHouseCup`（mixin_play.dart:1781）在学年切换时调用。

### 2.4 Player 相关字段（`lib/models/player.dart`）
- `houseCupPoints` / `houseCupSources`（本学年学院杯贡献）。
- 存档字段数当前 21（`progression_fix_test.dart` 硬编码，**新增字段必须 +1**）。

## 三、设计方案

### 3.1 赛季周期：跟随学期（term）
- **一学期一届**：第一学期（9-12月）为「秋季赛」，第二学期（1-6月）为「春季赛」。
- 复用 `worldState.term` 无需新增时间字段；学期切换点即赛季重置点。
- 判定：`duelNpc` 结算时对比存档的 `duelSeasonTerm` 与当前 `worldState.term`，
  不一致则重置本赛季积分/胜场/已领档位（保留累计总胜场 `duelSeasonWinsTotal`）。

### 3.2 赛季积分：复用 `/决斗` 自动累积（零新增操作）
- 每次 `duelNpc` **胜利**：赛季积分 +10（连胜 +2，最高 +18，防单调）。
- **落败**：+2 参与分（鼓励继续打，但不鼓励刷——有每日次数上限兜底）。
- 赛季积分与 `clubPoints`（社团日常积分）**独立存储、互不转换**——季度赛是专属玩法，
  不是社团积分的新来源（避免打乱 P14 晋升平衡）。

### 3.3 档位奖励（单玩家视角，不做 NPC 榜）
赛季积分分三档，达标即可领（`/决斗 赛季` 查看+领奖）：
| 档位 | 积分 | 奖励 |
|---|---|---|
| 新锐 | 40 | 社团积分 +30 · 反应速度 +3 · 学院分 +2 |
| 精英 | 90 | 社团积分 +50 · 勇气 +5 · 学院分 +4 · 声望（战斗）+1 |
| 冠军 | 150 | 社团积分 +80 · 魔咒掌握 +6 · 学院分 +6 · 声望（战斗）+2 · 称号「决斗赛季冠军」（收藏品） |

- 每档可领一次（`duelSeasonClaimedTier` 记录最高已领档），跳档只补差额。
- 领奖走 `addHouseCupPoints`（与 P18 口径一致，来源写「决斗社·秋季赛」等）。

### 3.4 面板与入口
- `/决斗` 面板（`formatDuelHelp` 或新增 `formatDuelSeason`）追加赛季状态：
  「秋季赛 · 赛季积分 X/150 · 胜场 Y」+ 领奖提示。
- `/决斗 赛季`：查看赛季详情 + 领奖。
- 不新增斜杠命令体系，全部挂 `/决斗` 子命令下（规划明确"复用 /决斗"）。

## 四、数据模型变更

Player 新增 5 字段（存档字段数 21 → 26，`progression_fix_test.dart` 同步 +5）：
```dart
int duelSeasonPoints = 0;      // 本赛季决斗积分
int duelSeasonWins = 0;        // 本赛季胜场
int duelSeasonWinsTotal = 0;   // 累计胜场（不随赛季重置）
int duelSeasonClaimedTier = 0; // 已领最高档位（0=未领）
String duelSeasonTerm = '';    // 赛季所属学期标识（'first-1991-1992'），用于重置判定
```

序列化 key：`duel_season_points` / `duel_season_wins` / `duel_season_wins_total` /
`duel_season_claimed_tier` / `duel_season_term`。

## 五、实现步骤（分批，每批跑 analyze + test）

1. **批次 A（数据层）**：Player 字段 + 序列化 + `progression_fix_test.dart` 字段数 +5。
2. **批次 B（结算钩子）**：`duelNpc` 胜负分支追加赛季积分累积 + 赛季重置判定

3. **批次 C（面板+领奖）**：`/决斗 赛季` 面板与档位领奖；`formatDuelHelp` 追加赛季行。
4. **批次 D（测试）**：`test/duel_season_test.dart`——积分累积/赛季重置/档位领奖/
   存档往返/防刷（每日上限仍生效）。

## 六、风险与边界

- **行为不变红线**：不动 `duelNpc` 现有胜负/好感/学院分/死亡逻辑，只在其结算尾部追加。
- **防刷**：每日次数上限 `canDoDaily('duel')` 天然兜底；落败 +2 参与分不设额外门槛。
- **赛季重置时机**：以 `duelNpc` 调用时对比 term 为准（延迟重置），避免在学期切换
  系统里加钩子（改动面小、无副作用）。
- **不做的**：NPC 赛季榜/对手 AI 动态成长/跨赛季总冠军称号（留待玩家反馈后再扩）。
- **与 UI 无关**：纯玩法层，不触碰本轮 UI 收敛工作区。
