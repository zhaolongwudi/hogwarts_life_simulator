## 二、现状勘察（2026-09-22 核实）
### 2.1 室友现状：仅是地点词/叙事泛指，无 NPC 实体
- **locations.dart:14**：`kDormLocation = '霍格沃茨·宿舍'` 固定地点；:66「室友」只是 `kHogwartsContextHints` 上下文线索词。
- **mixin_narrative.dart:3372 宿舍氛围池**：4 条环境描写（壁炉/校袍/猫头鹰/棋局），**全部是场景氛围、无一涉及具体室友人物**。
- **story_data_*.dart**：原著剧情里「室友」是泛指叙事（「你让室友先去」「买一大袋分给室友」），不指向具体 NPC。
- **NPC 模型（lib/models/npc.dart）**：无 `roommate`/`dormMate`/`dormId` 字段；NPC 靠 `currentLocation` 表达所在位置，无「宿舍归属」概念。

### 2.2 离线回合机制（室友小剧场的主战场）
- **`_runOfflineQuickTurn`（mixin_narrative.dart:1592）**：回合推进顺序 = P7 玩法路由 → P10 奇遇结算 → P11 羁绊结算 → P13 回信结算 → 常规叙事组装 → 世界事件追加。
- **`localEventLinesFor`（mixin_narrative.dart:3278）**：地点氛围池，`_locationEventLines` 精确匹配失败后走**子串双向匹配**——`currentLocation` 规范名「霍格沃茨·宿舍」含「宿舍」短名 → 可命中宿舍池；命中失败退化为 `_genericEventLines`。
- **世界事件追加段（mixin_narrative.dart:1721 起）**：`_settleAfterNarrative` 后把 turnCount 匹配的最新 `worldState.recentEvents` 追加到叙事末尾（离线模式也有「世界在动」）。

### 2.3 关键确认（本次勘察最有价值的锚点）
1. **宿舍氛围池 4 条纯环境句** → 升级为「专属室友 NPC」后，池里可注入**人物小剧场**（早课催起/深夜聊天/考前突击），让宿舍从「场景」变「有人」。
2. **localEventLinesFor 子串匹配** → 只要宿舍池 key 保持「宿舍」，新室友句自动被离线回合命中，**无需改触发逻辑**。
3. **NPC 无 dorm 归属** → 需在 NPC 模型加 1 个可选字段 `dormId`（零迁移，老档缺省 null 安全）。
4. **室友可以是「生成 NPC」（isGenerated=true）** → 复用 `/新NPC 生成` 链路（mixin_commands.dart:980 起），入舍时自动补一位室友，玩家零操作。

## 三、设计
### 3.1 概念：室友 = 同 dormId 的 NPC（宿舍归属字段）
- `NPC.dormId`（可选 String，零迁移）：宿舍标识（`'gryffindor_boys'` / `'slytherin_girls'` 等），null = 无宿舍归属（教师/幽灵/校外）。
- 玩家有 `player.dormId`（新字段，进宿舍时赋值）→ 同 dormId 的 NPC 即「室友」。
- 入舍时机：首次进入宿舍（`kDormLocation`）时若无室友 → 自动补 1~2 位生成 NPC（同学院同年级，isGenerated=true）并赋 dormId。

### 3.2 数据层：NPC 加 1 字段 + 宿舍池扩人物句
```dart
// lib/models/npc.dart
final String? dormId; // 宿舍归属（'gryffindor_boys' 等）；null=无宿舍
```
- **宿舍池扩充**（mixin_narrative.dart:3372）：4 条环境句保留，追加人物向小剧场句（带 `$roommate` 占位）：
  - 早课催起：「『再不起来要赶不上早餐了！』室友 $roommate 一把掀开你的被子。」
  - 深夜聊天：「熄灯后 $roommate 翻了个身，压低声音问你最近是不是有心事。」
  - 考前突击：「$roommate 把课本摊在桌上，说『这段我猜必考』，拉着你一起背。」
  - 共享夜宵：「$roommate 摸出一袋滋滋蜜蜂糖，分了半袋给你。」
- `localEventLinesFor` 触发时若玩家当前在宿舍且存在室友 → 优先取人物句（按 seed 轮换）；无室友则退回环境句（现状不变）。

### 3.3 互动入口（/室友 命令族，数据驱动接入 CommandRegistry）
- `/室友`（列表）：显示同 dormId 的室友 NPC + 各自好感/状态。
- `/室友 聊天`：随机一段深夜聊天小剧场（好感 +1，冷却 3 回合，走 updateNpcAffection 统一入口）。
- `/室友 早起`：室友催起事件（触发概率性；早起 +1 精力）。
- 接线模板：参照 /魁地奇（mixin_commands.dart:872 五要素）+ CommandRegistry 数据驱动（command_registry.dart:57/107），玩法逻辑写 mixin_roommate.dart（新文件）或并入 mixin_club.dart 旁的新 mixin。

### 3.4 宿舍小剧场池（离线回合高频来源）
- 在宿舍池人物句基础上，新增「室友互动小剧场」独立池（8~12 条），按 `seed = turnCount` 轮换；
- 只在玩家 `currentLocation` 为宿舍（含「宿舍」子串）时启用；
- 与氛围句互斥：有人物句命中就不叠加环境句，防叙事重复。

### 3.5 存档影响（零迁移优先）
- `NPC.dormId`：可空字段，老档缺省 null → **零迁移**；
- `Player.dormId`：新字段，老档 null → 进宿舍时惰性赋值 → **零迁移**；
- 生成室友 NPC：isGenerated=true，随 NPC 存档走 → 无版本迁移。

## 五、实现步骤（批次 A-D）
1. **批次 A（数据层）**：`NPC.dormId` + `Player.dormId` 字段；宿舍池扩充人物句 + 小剧场池。
2. **批次 B（命令层）**：`/室友` 命令族接入 CommandRegistry（列表/聊天/早起三子命令）。
3. **批次 C（逻辑层）**：入舍自动补室友（生成 NPC + 赋 dormId）；`localEventLinesFor` 人物句优先分支；聊天/早起结算（updateNpcAffection + 精力）。
4. **批次 D（测试）**：入舍补室友/老档无 dormId 安全默认/聊天好感+1 冷却/早起精力/宿舍池人物句命中/小剧场不与环境句叠加/存档往返。

## 六、风险与边界
- **行为不变红线**：不动现有宿舍氛围句与触发链；只新增 dormId 字段 + 池扩充 + /室友 命令。
- **零迁移**：两个 dormId 均可空、老档缺省 null 安全默认；生成室友走 isGenerated 现成链路。
- **不抢戏**：室友互动仅限宿舍场景（currentLocation 含「宿舍」）；小剧场走 seed 轮换，不与奇遇/羁绊/回信结算抢回合。
- **原著 NPC 不动**：不强行给原著角色（哈利/罗恩等）赋 dormId，避免 OOC 人设防线冲突；只补生成 NPC 当室友。
- **与 UI 无关**：纯玩法层，不触碰本轮 UI 收敛工作区（4 文件修改保持未 commit）。
