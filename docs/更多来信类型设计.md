## 二、现状勘察（2026-09-22 核实）
### 2.1 来信系统（P13，lib/mixins/mixin_letter.dart / lib/data/letter_data.dart）
- **三类来信**（`LetterKind` 枚举，letter_data.dart:49）：`friendship` 友情（门槛低会重播）/ `rivalry` 敌对（怨气对手挖苦）/ `milestone` 羁绊里程碑（once 不重播）。
- **数据模型**（letter_data.dart:52-79）：
  - `LetterDef`：id / kind / senderId（指定寄信人，null=按品格挑）/ minAffection / maxAffection / onceOnly / scene / effect / replies。
  - `LetterEffect`：senderAffection / galleons / housePoints / reputationDim+Value（四种效果）。
  - `LetterReply`：title + text + effect（回信选项）。
- **触发逻辑**（mixin_letter.dart:104 `maybeTriggerLetter`）：先处理挂起（奇遇/羁绊/回信），冷却 `kLetterCooldownTurns=9`，然后三分支——①未收里程碑（门槛高优先）→ ②友情随机 → ③敌对随机。
- **寄信人挑选**（mixin_letter.dart:55 `letterSenderFor`）：pool = **introduced && isAlive && !graduated** 的 NPC；senderId 指定则精确匹配（不在 pool 返回 null）；rivalry 按怨气挑、其余按好感挑，`_avoidRepeatSender` 防连发。
- **投递**（mixin_letter.dart:146 `_deliver`）：标题头 `🦉 猫头鹰来信 · ${sender.name}`，onceOnly 记 receivedLetters，有 replies 进 pendingLetterId，入信效果结算，`_archiveLetter(sender.name, def)` 固化存档。
- **存档落点**（mixin_letter.dart:169 `_archiveLetter`）：`p.letters.add(Letter(id, sender, content, date))`——**sender 只存字符串**（不是 NPC id），上限 50 条，/信 读 回看。

### 2.2 关键确认（本次勘察最有价值的锚点）
1. **`_archiveLetter` 只落 `sender.name` 字符串** → 无 NPC 寄信人（魔法部/匿名/机构）只需传自定义署名标签即可存档，**Player 零新增字段、存档零迁移**。
2. **`letterSenderFor` 过滤了 `!graduated`** → 「毕业旧友重联」需要放开 graduated NPC 通道（新机制点）。
3. **`_deliver` 标题头强依赖 `sender.name`** → 无 NPC 寄信人需支持「署名标签」兜底（senderLabel）。

## 三、设计
### 3.1 类型定义（LetterKind 扩展 3 值）
| 新 kind | 定位 | 寄信人 | 频率 | onceOnly |
|---------|------|--------|------|----------|
| `mystery` 神秘信件 | 悬疑彩蛋，低概率氛围 | 匿名（senderLabel=「匿名的寄信人」） | 低频随机 | 是 |
| `ministry` 魔法部公函 | 机构节点（O.W.L.s 报名/禁林警告/魁地奇许可） | 机构（senderLabel=「魔法部」） | 学期关键节点各一次 | 是 |
| `reunion` 旧友重联 | 毕业 NPC 来信（时空感） | graduated NPC（senderId 指定） | 毕业 NPC 存在时可触发 | 否（可重播） |

### 3.2 LetterDef 扩展（1 个可选字段）
```dart
final String? senderLabel; // 无 NPC 寄信人时的署名标签（魔法部/匿名/…）；null=用 NPC 名
```
- `senderId == null && senderLabel != null` → 机构/匿名信（不查 NPC pool，直接按冷却投递）。
- `senderId != null && senderLabel == null` → 走现有 NPC 通道（含 reunion 放开 graduated）。

### 3.3 触发优先级（不抢戏原则）
```
挂起处理（奇遇>羁绊>回信） → 冷却 9 回合
→ ① milestone（未收，门槛高优先，现状不变）
→ ② ministry（学期节点，未收且节点命中，低频）
→ ③ mystery（未收，低概率随机，彩蛋不抢主线）
→ ④ friendship（现状不变）
→ ⑤ reunion（毕业 NPC 在时，随机，靠冷却兜手感）
→ ⑥ rivalry（现状不变）
```
新类型全部插入 milestone 之后、friendship 之前（机构/彩蛋不压过羁绊缘分，也不挤占日常暖场）。

### 3.4 寄信人通道（letterSenderFor 微调）
- 新增分支：`def.senderLabel != null` → 直接返回「匿名寄信人」（哨兵标记），`_deliver` 用它兜底署名。
- reunion：senderId 指定毕业 NPC 时，pool 放开 `graduated == true` 的 NPC（仅 reunion kind 放开，其余 kind 维持现状）。

### 3.5 投递与结算（_deliver / _archiveLetter 微调）
- `_deliver` 签名：sender 可空，署名取 `def.senderLabel ?? sender.name`；标题头 `🦉 猫头鹰来信 · ${署名}`。
- `_archiveLetter`：sender 参数已是字符串，直接传署名标签，**零改动**。
- 结算走 `_applyLetterEffect` 现有四通道（好感/加隆/学院分/声望），机构信可用 housePoints+reputation，匿名信可用 reputation（dark 神秘感）。

## 四、示例条目（kLetters 追加，纯数据）
1. **letter_ministry_owls**（ministry，学期初）：O.W.L.s 报名通知；回信「确认报名」→ housePoints+5；onceOnly。
2. **letter_ministry_forbidden**（ministry，禁林相关）：警告信；回信「我会注意」→ 无效果（氛围向）；onceOnly。
3. **letter_mystery_riddle**（mystery）：匿名谜语信；回信解谜 → reputation.dark+2；onceOnly。
4. **letter_reunion_old_friend**（reunion，senderId 指定某毕业 NPC）：旧友重联寒暄；回信 → senderAffection+3；可重播。

## 五、实现步骤（批次 A-D）
1. **批次 A（数据层）**：`LetterKind` 加 3 值；`LetterDef` 加 `senderLabel`；`kLetters` 追加 4 条示例。
2. **批次 B（触发层）**：`maybeTriggerLetter` 插入 ministry/mystery 分支（milestone 后）；reunion 分支（friendship 前）。
3. **批次 C（寄信人/投递）**：`letterSenderFor` 加 senderLabel 哨兵 + reunion 放开 graduated；`_deliver` 署名兜底。
4. **批次 D（测试）**：ministry 学期节点命中/once 防重；mystery 低概率/不抢戏；reunion 毕业 NPC 通道；匿名信存档署名正确（/信 读 回看）；老档零迁移兼容。

## 六、风险与边界
- **行为不变红线**：不动现有三型来信的触发与结算；只新增 kind + 1 可选字段 + 若干条目。
- **不抢戏**：新类型全在 milestone 之后低频触发；mystery 用低概率 + onceOnly 双保险。
- **零迁移**：sender 本就存字符串，机构/匿名信署名直接落档，Player 零新增字段、存档版本不变（kSaveVersion=2）。
- **reunion 边界**：仅 reunion kind 放开 graduated NPC；其余 kind 的 pool 过滤维持现状（防毕业 NPC 乱入日常信）。
- **与 UI 无关**：纯玩法层，不触碰本轮 UI 收敛工作区（4 文件修改保持未 commit）。
