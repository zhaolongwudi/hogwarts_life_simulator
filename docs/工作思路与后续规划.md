# 霍格沃茨人生模拟器 · 迭代工作思路（P1~P14）与后续规划

> 给下一次接手维护的 AI 助手 / 开发者。
> 读懂这份文档，你就知道「这些系统当初为什么这么做、放在哪、下一步该往哪走」，
> 不必再靠读 git log 或翻一堆审查报告去还原来龙去脉。基线版本 v4.8.4（2026-09-18）。

## 一、总体工作思路：把世界变成「活的」而非「剧情树」

项目的玩法引擎（时间、学院、好感、职业、死亡…）v3.x 已基本成型。P1~P14 做的事，
本质上是回答一个问题：**当 AI 不在场（离线回合）时，这个世界凭什么还值得我继续点「继续」？**

主线收口成一条判断：**世界不因你而停转，但还得让「你」有关、可积累、有因果。**
每个阶段都按同一套路走：先补「发生了什么事」，再补「做了会怎样」，最后补「这跟我是谁有什么关系」。
落地上，这套「世界在动」的内容被切成一层层**小而自治**的模块，每层只做一件事，全部由数据表和
一个 mixin 承载，彼此用统一的互斥 + 冷却门控隔开，因此可以无限叠加而不互相打架。

给后续工作的一句话守则：**新增一层内容 = 一份数据 + 一个 mixin + 一段叙事接入 + 一个测试夹具开关 +
台账补一行。只写叙事不动状态的内容，算不上系统。**

## 二、P1~P14 逐层工作思路

下表按「问题 → 思路 → 落点」拆解。落点指向源码文件，方便直接定位。

### P0~P5：先让「离线」像回事（底座）

| 阶段 | 当时的问题 | 工作思路 | 落点 |
|---|---|---|---|
| P0 | 离线兜底叙事干巴重复，NPC 聊天答非所问 | 给本地兜底叙事做个性化，扩充 NPC 本地聊天词库 | `npc_chat_service.dart` / `npc_chat_wordbank.dart` |
| P1 | AI 挂了就只会出冷冰冰的兜底模板 | 把「叙事来源」抽象出来，支持 AI 与本地自动降级切换 | `mixin_narrative.dart` / `app_provider.dart` |
| P2 | 用户不知道现在是 AI 在写还是本地在写 | UI 更名为直白的「本地模式」，加可选 AI 润色开关 | `app_provider.dart`(narrativePolish) |
| P3 | 本地聊天的腔调太单薄 | NPC 本地聊天回复接入同一套 AI 润色门控 | `npc_chat_service.dart` |
| P4 | 可信度无感知 | 主屏/设置加「叙事来源 + 润色状态」徽标反馈 | 主游戏 UI |
| P5 | 事件池稀薄、规范名命不中 | 扩充本地事件池，修规范名命中 | `data/` 事件池 |

这一段的意义是打地基：先把「离线」做成一个**有解析、可降级、可告知**的稳定底座，后面的一切
「世界在动」内容才能放心往上堆。

### P6~P8：让「你做的事」产生结果（因果）

| 阶段 | 当时的问题 | 工作思路 | 落点 |
|---|---|---|---|
| P6 | 离线回合输入「我在练咒」毫无变化 | 做本地行动后果引擎：判定行动类型 → 结算属性/状态/金钱 → 写回叙事 | `mixin_offline_consequences.dart` |
| P7 | 后果引擎做完了，但「去打魁地奇」只加一条干巴巴结果 | 自然语言玩法意图路由：识别魁地奇/决斗/禁林/宠物，直连完整玩法系统 | `mixin_play.dart`(tryRouteGameplayIntent) |
| P8 | 直连玩法后输赢太单调 | 魁地奇赛果变体 + 禁林特殊遭遇 + NPC 回忆收集 | `mixin_play.dart` |

P6 是承上启下的关键：它把「离线行动」从纯叙事升级为**有状态结算**，后续的节庆、奇遇、社团全靠它
对「这回合你做了什么」的判断来挂钩。

### P9~P14：让「世界有它的节奏，也记住你这个人」（层面叠加）

这六层是「世界在动」的主体。共同模式：**数据收口在 `data/`，逻辑收口在对应的 `mixin_`，接入离线
叙事管线，专项测试用 `batch3x/4x` 隔离。**每层都有一个「克制点」，避免无限刷屏。

| 阶段 | 一句话定位 | 关键克制点 | 落点 |
|---|---|---|---|
| P9 年度节庆 | 节日是「今天恰好特别」，按日期、每学年一次 | 学年去重，不年年重放 | `festival_data.dart` / `mixin_festival.dart` |
| P10 奇遇 | 随机落在「你」身上的两段式小故事 | 触发回合给选项、下回合结算；加权抽取 + 冷却；按季节/地点/年级过滤 | `happenstance_data.dart` / `mixin_happenstance.dart` |
| P11 羁绊小剧场 | 好感跨门槛后与亲近之人的跨回合小戏 | 前幕自动演、最终幕待抉择（覆盖承接选项） | `companion_arc_data.dart` / `mixin_companion_arc.dart` |
| P12 宠物小插曲 | 宠物偶尔有自己的生活 | 门槛低重播的日常插曲 + 亲和 25/55/85 各一次里程碑；无选项不结算 | `pet_story_data.dart` / `mixin_pet_story.dart` |
| P13 猫头鹰来信 | 已结识 NPC 主动寄只言片语 | 友情重播/敌对挖苦/里程碑各演一次；带牵念的信进待回信、下回合真回信 | `letter_data.dart` / `mixin_letter.dart` |
| P14 校园社团 | 让「你属于什么」成为持续成长的线 | 四社五阶积分晋升；行动对得上干系事才记分；自带冷却 | `club_data.dart` / `mixin_club.dart` |

P9~P14 的关系值得点透：

- P10~P13 是「落在你身上的事」——来了又散，留不下身份；P12/P13 已经埋了「重复不刷屏」的痕迹。
- **P14 是转折点**：它不新增「一件发生的事」，而是加了一条**可积累的身份线**。前 13 层给的是「事件」，
  P14 给的是「归属与成长」，这让离线内容从「看片」变成「经营」。后续规划都围绕这个转折展开。

## 三、接入架构：离线叙事管线（改这块必读）

所有 P9~P14 内容都挂在**同一条离线叙事管线**里拼接，顺序有讲究。核心在 `mixin_narrative.dart`
的离线回合流程，拼接顺序是：

```
世界事件补齐（本条 turnEvent 追加进叙事）
  → P9 年度节庆（celebrateFestival）
  → 原著剧情线注入（dueCanonEvents，id 带 canon_ 前缀去重）
  → P6 行动后果引擎（【行动结果】…）
  → P14 社团活动（maybeRunClubActivity，源自本回合行动）
  → P10 奇遇（triggerHappenstance，浮在日程上、给专属选项）
  → P11 羁绊（maybeTriggerCompanion，最终幕待抉择）
  → P12 宠物小插曲（maybeTriggerPetStory，无选项）
  → P13 猫头鹰来信（maybeTriggerLetter，待回信）
  → 承接选项：buildFallbackChoices → companionChoices → happenstanceChoices → letterReplyChoices
```

四条铁律：

1. **表白回合（confessedThisTurn）整条跳过**，各层都带 `if (!confessedThisTurn)`，避免和「接受/婉拒」抢注意力。
2. **互斥门控在各自 mixin 内**：有奇遇/羁绊/待回信时，别的层先不抢戏；每层自带冷却，防刷屏。
3. **选择优先级**：羁绊最终幕 > 奇遇专属选项 > 来信回信选项 > 兜底承接。越低优先级越容易被更高优先级覆盖。
4. **新增一层要同时想清三件事**：它在管线里的位置（顺序）、它的专属选项优先级、它的冷却/去重口径。

## 四、测试与开关约定（最容易踩坑）

- 每个系统都有开关键，全部在 `app_provider.dart`：`happenstanceEnabled` / `companionArcEnabled` /
  `petStoryEnabled` / `letterEnabled` / `clubEnabled`，另有全局 `offlineQuickMode`。
- 共享测试夹具 `makeGame`（`test/helpers/test_fixtures.dart`）默认把这些「新增随机内容」**全部关掉**，
  免得扰动 1900+ 既有确定性用例对 choices/叙事的断言。专项用例（如 `batch43_club_test.dart`）在自己的
  fixture 里再逐个打开。**新加一层必须照做**。
- 每个系统的专项测试独立成文件：`batch38`(festival) 至 `batch43`(club)，覆盖「数据完整性 + 加入/退出 +
  门控过滤 + 匹配记分 + 面板 + 存档序列化」，并补一条「老档无该字段时安全默认」。
- 确定性随机用 `Random(turnCount)`（以回合号做种子），保证同一起点可复现；这也是测试能锁死的关键。

## 五、后续内容规划（按优先级与依赖排序）

P14 后世界有了「身份 + 成长」轴，规划围绕把这条轴做深、把已铺的层面互通起来，再做工程收口。

### 第一梯队：深化 P14 社团，让「归属」真正有回报

- **跨回合社团任务**：目前社团只在回合开始时被动攒分。加「社团任务」——每周一条可选的专属委托，
  接了下一回合推进，完成给大额积分 + 专属奖励。复用 P9 周计划 / P6 后果引擎的接入点。
- **社团 × 学院杯联动**：让社团贡献与学院杯挂钩（现有 `addHouseCupPoints`），社团排名反过来影响
  校园叙事与特产奖励，把 P8 学院杯与 P14 社团拧成一根。
- **社团专属小玩法**：决斗社季度赛（复用 `/决斗`）、魔药部限时配方（复用 `/使用` 药水）、魁地奇队训练
  （复用 P8 变体）、快讯社头版事件（复用 P10 奇遇池）。每社给一个可玩入口，别只做标记记分。
- **同好 NPC 关系注入**：社团成员的「眼缘」影响 P11 好感，让「因为是同好」成为关系推进的一个理由。

### 第二梯队：让已有层面互相咬合（交叉，收益高）

- **来信 → 社团 / 来信 → 羁绊**：P13 的信可以为 P14 社团牵线（社长来信拉你入社），或为 P11 羁绊送
  剧情弹；已有多套「待回信/待抉择」旗标，做串联前先定互斥优先级。
- **社团 → 来信回访**：晋升到王牌/传奇时，同好回一封信（复用 P13 里程碑逻辑）。
- **奇遇结果的长期痕迹**：P10 结局目前多为一次性数值；可沉淀为角色档案条目，汇入终章、映进 P14 声望。

### 第三梯队：扩展面（有收益、风险低、可后置）

- **室友系统**：把 `locations.dart` 里的「室友」从地点词升级为专属室友 NPC 档案（宿舍归属、早课催起、
  深夜聊天），既补框架2 §31，又给离线回合新增一个高频小剧场来源。注意这是新领域，走完整八步流程。
- **社团 × 显示模式**：若做优先做「沉浸模式隐藏好感值」的统一（框架2 §10），当前 `simulationStyle`
  三态仍是「字段在、行为未做」，属明确暂缓项，别重复实现。
- **更多来信类型**：神秘信件、魔法部公函、毕业多年后旧友重联——现有 `letter_data.dart` 是纯数据表，
  加类型成本低。

### 工程与质量收口（随时可做）

- P9~P14 目前是 6 个独立 `batch3x/4x` 测试文件，可加一条**跨层互斥综合用例**（同一回合多层同时可触发时，
  验证互斥优先级与叙事顺序符合 §三），把这套「世界在动」的行为契约钉死。
- README / PROJECT_GUIDE / 框架对照台账三类文档应随每次功能迭代同步，避免再度漂成 v3.9 对 v4.8 的鸿沟。

### 明确不做的（别再投入）

哑炮玩家线（已删）；世界线偏离后的全量重推演（依赖 AI 能力）、显示三态完整化（单机无收益）——见
`.github/archive/框架对照维护台账.md` 第四节。

## 六、给接替者的一句话方法论

> 每加一层「世界在动」，先问它落在哪根轴上：**让世界更有节奏（节庆/事件）、让你做的事更有结果（后果/
> 玩法直连），还是让你更有归属与成长（羁绊/社团）。** 前两类做多了会饱和，第三类才是 P14 之后能持续
> 塞内容而不腻的口子。数据表里能表达的，别写死在叙事里；能测试锁死的互斥，别指望提示词管住。
